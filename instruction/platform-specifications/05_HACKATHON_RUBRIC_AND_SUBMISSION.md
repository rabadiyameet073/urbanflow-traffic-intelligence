## 5. Judge Q&A (answers must match the repo)

| Question | Short answer |
|---|---|
| Is the −X % real? | Generated by `pnpm bench`: paired seeds, bootstrap CI, held-out seeds. Parity case shown honestly. |
| Why not a better fixed-time plan? | Fixed-time wins on steady balanced demand (we show it). Adaptive wins on uneven/changing demand; the switching-cost guard is why. |
| What does the AI control? | Nothing directly. Bounded proposals → Kernel → twin what-if → human Approve. |
| What if the AI hallucinates? | zod structured outputs, evidence required, numbers must come from input, fallbacks, eval table vs heuristic. |
| How do you know signals can't conflict? | Property tests, exhaustive state BFS, differential vs independent reference, mutation kill rate. |
| Real hardware? | Simulation only; NTCIP-inspired mapping; real deployment needs a certified controller, conflict-monitor unit, engineering sign-off. |
| Why >150 m for EVP? | ETA 10 s < ≈ 13.5 s needed (yellow + all-red + pre-clear); show the sweep. |
| Is Kafka/Spark needed? | For observation, storage, anomaly detection, scale path; the control loop does not depend on it by design. Latency numbers shown. |
| Beyond an API call? | Muse Code built it; Spark with structured outputs, function calling, image input; SAM masks; Muse Image robustness; closed loop. |
| Cost? | ≈ $0; free tiers; capped AI calls; fallbacks; cost meter in UI. |
| EVP abuse? | HMAC, timestamp window, nonce replay, rate limits, plausibility, storm guard; forged-request demo. |
| Next? | Corridors, pedestrian phases, RTSP edge tracking, hardware-in-the-loop, DoT pilot. |
